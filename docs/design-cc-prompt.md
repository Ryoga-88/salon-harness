# Salon Harness — Cursor Composer 向け UI/画面デザインプロンプト

この文書全体を Composer に渡し、「Next.js アプリとして実装可能な高密度の管理画面一式」を作成してもらう用途を想定しています。**美容室向け SaaS**。Instagram 経由の集客 → LINE 友だち化 → LIFF で予約 → クーポン・リマインドまでを**サロンオペレーターが1つの管理画面**から扱う前提です。

---

## プロダクト概要（デザイン判断の共通文脈）

- **名前**: Salon Harness  
- **立ち位置**: オープンソースの `line-harness-oss`（LINE・友だち・DM）および `ig-harness-oss`（Instagram Engagement Gate）を **HTTP API で連携**。本体はコードに同梱せず、別デプロイの Worker を叩く。  
- **統合キー**: 顧客の主キーは **UUID（`friend_id` / harness 共通）**。`identity_links` で IG と LINE を突き合わせる。  
- **ユーザー**: サロンオーナー／受付／スタイリスト（ロールにより予約一覧のスコープが変わる想定）。  
- **トーン**: 業務効率優先。**装飾より情報階層・余白・一貫したコンポーネント**。モバイルでも最低限の閲覧・操作ができること（現状コードはサイドバーが10項目あり、狭幅では5項目のみ表示という制約あり。デザインで改善してよい）。

---

## 技術・実装前提（Composer に守らせたいこと）

- **フレームワーク**: Next.js（App Router）、既存は `apps/web`。  
- **スタイル**: グローバル CSS 変数ベース（下記トークン）。必要なら Tailwind 導入やコンポーネントライブラリ化は OK だが、**見た目の意味（色・角丸・階層）は維持または意図的にリブランド**と明記すること。  
- **アイコン**: 現状 `lucide-react`。差し替え可。  
- **言語**: UI 文言は **日本語**（短く、業務用）。  
- **ダークモード**: 必須ではない。将来用にトークン設計だけしてもよい。

## グローバルレイアウト仕様（AppShell）

- **左**: 固定またはスティッキー縦ナビ。ロゴ/プロダクト名「Salon Harness」。各項目は **アイコン + ラベル**。アクティブは背景 `#e6f3f1`、文字色アクセント。  
- **右**: メイン。上から **ページタイトル（h1）** → 必要なら一段の説明（muted）→ ツールバー → コンテンツ。  
- **ツールバー**: 左寄せボタン群（更新・作成・フィルタ等）、`gap: 10px`、`flex-wrap`。  
- **トースト / インラインエラー**: エラーは **ローズ系 `#be123c`**、成功は **アクセント系 `#0f766e`** で既存コードに合わせるか、統一パレットを定義。

## 画面別詳細仕様

以下、**ワイヤーフレームレベルで Components を列挙**。Composer は Figma 的ラフでも、React のページ構造でもよいが、**状態（空・ローディング・エラー）**まで指定すること。

### 1. `/login`

- ビューポート中央の **カード（max 440px）**。  
- フィールド: メール、パスワード、区切り、「または API Key」。  
- 主ボタン: ログイン。  
- エラーはカード上部に表示。  
- フッターに「公開トップへ」リンクがあってもよい。

### 2. `/`（公開サロン検索）

- ヒーロー: タイトル「登録サロンを探す」、短い説明。  
- 検索バー + 「近くから探す」トグル風ボタン。  
- **サロンカード Grid**（自動フィット、`minmax(240px,1fr)`）。カード: アイコン、サロン名、サブテキスト。  
- 「サロンを登録する」コール・アウト。  
- エラー時: 明示的なメッセージ色。

### 3. `/admin` ダッシュボード

- **KPI 行**: 3 カラムカード「今日の予約」「今週の売上」「統合済みチャネル（IG+LINE 同一 UUID 数など）」。数値は大きく（`.metric` 相当）。  
- **ファネル要約パネル**: 箇条書きまたはミニチャート。「予約がある顧客数」「IG 連携数」「LINE identity」等。リンク「ファネルを開く」→ `/analytics`。  
- **クイックアクション**: 「予約を追加」「クーポン発行」「キャンペーン作成」。  
- **今日のタイムライン**: 空状態の説明。「今後 Worker 連携で予約を流す」と分かる placeholder。  

### 4. `/reservations`

- ツールバー: 「更新」。  
- **テーブル**: 列「日時」「顧客（UUID はリンク、`/customers/{id}`）」「ステータス」「金額」。  
- 空状態: 「予約はまだありません」。  
- ログイン未取得時は muted メッセージ。

### 5. `/stylists`

- 上部: **サロンセレクト** + 更新。  
- **新規フォームパネル**: 所属サロン、名前、表示名、メール、得意メニュー（カンマ区切り説明）、プロフィール textarea、登録ボタン。  
- **グリッドカード一覧**: 表示名 / メール / プロフィール抜粋。

### 6. `/customers` 顧客一覧

- 冒頭説明（1〜2文）: 「LINE は line-harness、統合は identity_links」と技術は短く触れるか、ユーザー向けに「チャネル横断」とだけ書いてもよい。  
- ツールバー: 「更新」。  
- **LINE Harness 未設定の注意バナー**（任意・アラートスタイル）。  
- **データテーブル**: 表示名 / 統合 ID（ monospace 折返し）/ チャネル（「IG」「LINE」ラベルのチップでも可）/ 予約数 / 最終予約 / 行末「タイムライン」ボタン→ `/customers/[id]`。  
- 行ホバーで背景がわずかに変わるとよい。

### 7. `/customers/[friendId]` 顧客タイムライン

- **戻る**（一覧）、**更新**。  
- タイトル「顧客タイムライン」、サブ見出しに表示名、下に monospace の UUID。  
- **イベントタイムライン**: 縦リスト。左にカラーラインで種類を示す。
  - `identity.*` → ティール系  
  - `reservation.*` → ブルー系  
  - `coupon_used` → イエロー/アンバー系  
  - `karte` → パープル系  
  - `automation.*` → スレート系  
  各行: 日時（小）→ 見出し → サブ文言。  
- **identity_links 表**: ソース / external_id / 作成日時。  
- フッター導線: 「メッセージを送る」→ `/messages?friend_id=`。

### 8. `/menus` / `/coupons` / `/settings`

- 一覧 + フォームが中心。 Composer は **既存の業務フォームパターン**（`.panel.form`, `.field`）に統一。  
- エラー・成功フィードバック領域を必ず確保。

### 9. `/campaigns`

- パネル「IG Engagement Gate 作成」。  
  - テンプレ select（名前 + キーワード表示）。  
  - LINE 友だち追加 URL。  
  - 任意: クーポンコード。  
  - 任意: 対象投稿 ID（カンマ区切りヒント）。  
  - 主ボタン「作成」。  
- **情報パネル（効果計測）**: `ref` / `coupon` クエリでトラッキングする旨、harness 側で詳細ログを見る旨を **折りたたみ可能 Info** にするとスッキリ。

### 10. `/messages`

- フォーム: `friend_id`、本文 textarea、送信。  
- `?friend_id=` でプリフィル想定。**ヒントテキスト**で「顧客タイムラインから飛んでくる」ことを書く。

### 11. `/analytics`

- 導入文: 「粗いファネル。細かいコメントログは ig-harness / line-harness」。  
- ツールバー: 「更新」「顧客一覧」。  
- **セクション「全体」**: 横向きバーチャート（Instagram UUID 数 / LINE UUID 数 / ブリッジ数）。最大値で正規化。  
- **セクション「コホート」**: 「予約がある顧客に絞った」指標。**スタイリストのみ**の注記を出せる領域。  
- Note 文言用のmutedエリア。

## 状態設計（全画面共通）

 Composer は各一覧に対し、以下を視覚的に区別:

1. **初期ローディング**（スケルトンまたはスピナー）  
2. **空データ**（イラスト不要。短い日本語 + 一次 CTA があれば可）  
3. **認証エラー**（ログインへ誘導）  
4. **API / ネットワークエラー**（再試行ボタン）  
5. **403**（権限なしの説明）

## 備考（実装済み機能との同期）

実データは Cloudflare Workers API 経由。デザインモック時は **ダミーの JSON** でよいが、項目名は次を意識:

- `friend_id`（UUID）  
- `identity_links.source` が `ig` | `line`  
- `/api/analytics/funnel` の `cohort` と `global_identity`

以上。
